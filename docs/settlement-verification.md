# 支払者・負担割合・精算の確認（Phase 2・項目3）

[記録0020](./implementation-log/0020-settlements.md)が実装判断と検証結果の基準です。160単体・全統合/PWAと公開smokeが成功。2026-10-23に案内①〜⑥へ本人が「全て確認した」と回答し、項目3完了。

## 動作の約束

- 精算対象支出の支払者と負担割合で、月別の元の精算額を計算します。折半101円なら支払者51円・相手50円です。記録者は支払者と別です。
- 旧支出は未設定・対象外です。対象外でも収支・予算実績に含みます。収入は精算対象になりません。
- 精算金は実際に支払った記録です。銀行送金や収支への二重計上は行いません。対象月と支払日は別で、翌月に払っても指定月へ適用します。
- 全額・部分払い、残額を超える支払いや逆方向の支払いを確認して記録できます。元の精算額は残り、残額だけが減ります。過払いは逆方向の差額です。
- 取消は元記録・取消者・日時を保持します。修正は取消後の再登録です。支出の修正・削除は元の精算額を再計算しますが、支払済み記録は残ります。
- 全期間は月別未精算の相殺後差額です。合計0円でも互いに逆向きの未精算月があれば、その一覧を残します。全期間一括の支払済み操作はありません。
- 同時操作で月の版が変わった場合は拒否し、入力を保持します。最新状態を確認して再確認するか、フォームを閉じて開き直します。

## 本人確認手順

既存プレビューを`settlement-check`へ更新し、iPhone＋Mac／Chrome・テスト用2アカウント/世帯で行います。実生活の金額、メール、パスワードやコードを共有する必要はありません。

1. 家計で架空支出101円を支払者＝自分、負担50:50、精算対象で追加します。相手へ即時反映し、支払者側の負担51円・相手50円、精算額50円になることを確認します。割合変更、対象外と旧明細の未設定表示も確認します。
2. 精算で相手から自分への20円を部分払いとして記録します。元の精算額50円を残し、残額が30円へ即時更新されることを確認します。残額を精算済みにして月の残額0円・全期間から当月の未精算が消えることを確認します。
3. 記録の取消はキャンセルなら維持、確定なら残額へ戻り、記録者と取消者が自分/相手として正しく表示されることを確認します。
4. 支払済みの元の支出を編集すると差額が再計算され、支払い記録が消えないことを確認します。過払いの確認案内と逆方向の差額、対象月と異なる支払日でも指定月へ適用されることを確認します。
5. 月を切り替え、月別の元の精算額・記録が分かれ、全期間の未精算一覧と相殺後差額を確認します。精算金が収支合計・予算・ホーム支出を増減させないことも確認します。
6. 両端末の再起動、片方のログアウト時の非表示・再ログイン後の復帰を確認します。
