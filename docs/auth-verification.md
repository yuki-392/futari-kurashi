# 認証の検証手順（Phase 1・項目2）

[実装記録0004](./implementation-log/0004-email-auth.md)に判断・設定・結果を残します。世帯やデータ共有は今回の対象外です。

## 自動検証

```sh
npm ci
npx playwright install chromium
npm run check
npm run test:auth
npm run test:pwa
```

`test:auth`は世帯画面への認証ゲートも確認するため、AuthとFirestore Emulatorを起動し、架空プロジェクト`demo-futari-kurashi`と`example.test`の架空アカウントを使用します。項目3からJDK 21が必要です。Authは9099番、Firestoreは8080番、Viteは5176番ポートを使用します。環境設定は[世帯検証手順](./household-verification.md)を参照してください。別のEmulatorが動いている場合は終了してから実行してください。

登録・未確認メールの制御・メール確認・トークン更新・ブラウザープロファイルを維持した終了/再起動・ログアウト・再設定・旧パスワードの拒否・新パスワードでのログインを確認します。実メールは送りません。テスト用ブラウザーのプロファイルは一時フォルダに作成し、終了時に削除します。Emulatorに永続データのexportは指定しません。

## 実サービスの準備

- プロジェクト: `futari-kurashi-5fcab9`
- Webアプリ: `Futari Kurashi Web`（登録済み）
- `.env.local`にWebアプリの公開設定を配置（Git対象外）。管理者用の秘密鍵は不要。
- Firebase ConsoleでAuthenticationを初期化し、メール/パスワードを有効化する。メールリンク認証は使わない。
- パスワードポリシー: 必須モード、最低12文字、文字種の強制なし。
- メールアドレス列挙保護を有効にする。
- 承認済みドメインに検証用Hostingドメインとlocalhostを追加する。
- Sparkのままとし、請求先や有料サービスは追加しない。

Firebase標準のメールアクションページを使用します。確認メールのリンクを開いた後はホーム画面アプリへ戻り、「確認しました」でユーザー情報とトークンを更新してください。Safariとホーム画面アプリのログイン状態が同じであることは前提にしません。

設定はAPI再取得で確認済みです。認証版の[検証URL](https://futari-kurashi-5fcab9--pwa-check-uol8w76f.web.app)は**2026-10-26 13:46（日本時間）**まで有効です。

## iPhone実機

現在のビルド識別子は`auth-check-fix1`です。ホーム画面アプリで更新通知が出たら適用してください。登録ボタンが無反応との指摘を受けた修正版です。入力不備があればボタンの上に理由を表示します。登録が進むかを再確認し、まだ無反応ならメッセージの有無のみを伝えてください（入力内容は不要）。

1. 「新規登録へ」から自分のメールと12文字以上のパスワードを入力する。未確認の間は共有準備画面に進まない。
2. 確認メールを受信してリンクを開く。アプリへ戻り「確認しました」で「ログインしています」に切り替わる。
3. アプリを終了し、ホーム画面から再起動してログイン状態が残る。
4. ログアウトするとログインフォームに戻る。再起動してもログアウト状態を維持する。
5. メール/パスワードで再ログインできる。
6. ログアウト後、「パスワードを忘れた方」から再設定メールを受け取る。Firebase標準ページで新しい12文字以上のパスワードを設定する。
7. 古いパスワードではログインできず、新しいパスワードでログインできる。

パスワード・メール内のコードやリンクをチャットや実装記録に貼らないでください。操作ごとの成功/失敗だけ教えてください。メールが届かない場合は迷惑メールも確認し、送信を繰り返す前に状況を伝えてください。
