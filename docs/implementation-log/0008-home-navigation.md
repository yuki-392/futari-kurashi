## 目的と対象要件

[製品仕様](../product-spec.md)のホーム・画面構成と、承認済み項目6の計画に対応する。実際の世帯情報と6画面の入口を用意し、家事・買い物・片付け・家計のデータ機能は追加しない。

## 実装前の方針

認証・所属の確認後にホームを表示する。設定に既存の招待・メール表示・ログアウトをまとめる。緑・白の配色、下部ナビゲーション、更新通知とビルド識別子を維持する。自動検証後、既存pwa-checkへhome-checkを7日間公開し、本人のiPhone確認を待つ。

## 判断と理由

### D1: ハッシュで6画面を切り替える

追加依存なしで直接アクセス・再読み込み・戻る/進むに対応する。URLには画面名だけを置き、個人情報やコードを含めない。不明な画面はホームへ正規化する。認証変更時はホームへ戻し、起動時の既存セッションでは指定画面を維持する。

### D2: Providerを画面より上に維持する

既存Auth/Household Providerと購読を共有する。未所属・確認中・取得失敗は準備画面を表示する。設定の招待フォームは画面を離れると破棄し、所属や認証の保存方式は変更しない。API・スキーマ・Rules・Firestore購読は追加変更しない。

### D3: 実装済みの情報だけを表示する

ホームは世帯名・人数・参加状況と入口を表示する。データ未実装部分は準備中と明示する。0件/0円など取得していない値を実データとして表示しない。

### D4: PWAと下部操作を両立する

44px以上の操作領域、safe area、本文の下部余白を確保する。更新通知はナビゲーションより上に表示し、切り替え時に先頭と見出しへ移動する。ブラウザー検証は「所属後ホーム→6画面移動→設定招待→参加反映→再起動/ログアウト」の流れ。Browser plugin not availableのため既存Playwrightを使い、390px/320pxとPC幅で確認する。
