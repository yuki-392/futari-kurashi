## 目的と対象要件

[製品仕様の家計管理](../product-spec.md)に沿って、収入・支出の手動記録とカテゴリ管理を追加する。今回は明細、カテゴリ、月別一覧と収入/支出の合計まで。予算、支払者・負担割合・精算、買い物連携、ホームの金額表示は後続項目とする。

## 実装前の方針

家計画面に月移動、月別明細、合計、収入/支出登録・編集・削除、カテゴリ追加・名称変更・アーカイブを設ける。標準カテゴリは収入（給与・賞与・その他）と支出（食費・日用品・住居費・水道光熱費・通信費・交通費・家具家電・医療・娯楽・その他）。初回利用時に世帯へ冪等に用意する。明細は1円以上の整数、内容、日付、カテゴリ、任意メモを持つ。

確認済みの認証・世帯・Firebase初期化を再利用する。TDDでモデル、Rules、Emulator/2ブラウザー検証を行い、検証成功後にRules/必要なインデックスを専用プロジェクトへ反映してfinance-checkをプレビューへ公開する。本番Hostingは変更しない。

## 判断と理由

### D1: 世帯ごとのカテゴリを安定IDで保持する

- 採用する方法: 標準カテゴリも世帯配下文書に冪等に作成し、名称変更後もIDは維持する。ユーザー追加も同じ形式とする。
- 理由・根拠: 複数端末で名称を共有し、明細からカテゴリを安定して参照できる。
- 検討した代案: 表示名だけ明細へ複製する方式は、カテゴリ編集と過去明細の整合が失われる。
- 制約・不利益: 初回にカテゴリ初期化の読み書きが発生する。
- 判断の状態: 採用中。

### D2: 使用中カテゴリをアーカイブする

- 採用する方法: 物理削除せずarchived状態にし、新規入力から除く。既存明細では参照カテゴリの名称を表示する。
- 理由・根拠: ユーザー選択。過去明細の分類を維持する。
- 検討した代案: 使用中カテゴリを削除して未分類にする、別カテゴリへ一括再分類する。
- 制約・不利益: アーカイブ後も履歴表示のためカテゴリ文書を保持する。
- 判断の状態: 採用中。

### D3: 月合計は家計画面だけで算出する

- 採用する方法: 表示対象月の取得済み明細から収入合計・支出合計を表示する。予算残額やホーム集計は実装しない。
- 理由・根拠: ユーザー選択。予算は後続項目で追加する。
- 検討した代案: ホームにも合計を表示する。
- 制約・不利益: 月内の全明細取得が必要。表示件数制限がある場合は合計の完全性も保証する必要がある。
- 判断の状態: 採用中。

### D4: 世帯内アクセスをRulesで限定する

- 採用する方法: 世帯配下に明細とカテゴリを保存し、確認済み同世帯メンバーだけを許可する。直接SDK、異常入力、一覧制限、競合をEmulatorで検証する。
- 理由・根拠: 既存のデータ機能のセキュリティ方針を維持する。
- 検討した代案: UIだけで隠す方式は採用しない。
- 制約・不利益: Rules式上限とクエリ形状を検証する必要がある。
- 判断の状態: 採用中。

### D5: Firestoreの単一フィールド索引は追加定義しない

- 採用する方法: `financeCategories.type`単独の並べ替えはFirestoreの標準単一フィールド索引を利用し、複合インデックス定義には含めない。明細の`date`+`createdAt`複合インデックス2件だけを追加する。
- 理由・根拠: デプロイ時にFirestore APIが`financeCategories`の単一フィールド複合索引は不要で、single-field index controlsを使うよう返した。既定索引を使うクエリに不要な複合索引を作成しない。
- 検討した代案: カテゴリ型の単一フィールド複合インデックスを明示する。
- 制約・不利益: 単一フィールド索引の挙動はFirestoreの標準設定に依存する。
- 判断の状態: 採用中。初回インデックスデプロイはAPIにより拒否され、不要定義を除いた後に2件のデプロイは成功。データ・Rulesへの影響はなかった。

## 指摘と対応

### R1: 明細登録後に収入・支出合計がすぐ更新されない

- 受付日: 2026-10-21
- 対象: D3、家計画面のFirestore購読と合計表示
- ユーザーの指摘: 「すべての項目ok。ただ、収入合計、支出合計が登録後即時反映されないのは気になる。一旦別の画面いかないと反映されない」
- 対応方針と理由: 購読更新で毎回新しい配列を発行し、Reactのメモ化した合計が更新を検知できるようにする。画面を離れて戻らなくても更新される回帰テストを追加する。
- 修正内容・関連記録: `watchFinanceEntries`は内部マージ用配列を維持しつつ、購読コールバックへ毎回ソート済みの新配列を返すよう修正。これにより`FinancePanel`の`useMemo`が依存配列の変更を検知する。
- 再検証の結果: 新しい配列を返し以前の配列を変更しない回帰テストは修正前に失敗・修正後に成功。130単体テスト、`npm run check`、全`npm run test:integration`、家計専用2ブラウザー検証が成功。finance-check version `186199409d859a57`へ再公開。当時は修正版の実機確認未実施。2026-10-22に本人確認済み。
- 対応状態: 対応済み
- ユーザーによる修正確認: 確認済み（2026-10-22「確認もok。次いこう」）

統合テストで検出した旧「未実装パス拒否」テストとの重複は、家計パスの専用テストへの移管で解消しました。インデックスAPIの応答に従った定義調整はD5に記録しています。
