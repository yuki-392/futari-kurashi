## 判断と理由

### D1: 同じFirebaseプロジェクトの標準URLへ初回公開する

- 採用する方法: https://futari-kurashi-5fcab9.web.app を使用し、Hostingだけを明示プロジェクトIDで公開する。Spark/請求先未接続と既存Auth/Firestore/データ/Rules/インデックスを維持する。
- 理由: 本人が標準URLとテスト用アカウントでの最終確認を選択。ドメイン購入やデータ移行を増やさず、検証済み機能を使える。
- 代案・制約: 別プロジェクトや独自ドメインは使わない。公開前のliveにはリリースがない。検証済みpreview版9522053e0ae6cb06を復旧候補として存在確認する。
- 判断の状態: 採用中。

### D2: 公開ビルドを識別し、本番originでPWAを追加し直す

- 採用する方法: フッターの「開発中」だけを除き、VITE_APP_BUILD_LABEL=phase1-releaseを維持。Emulator=falseでビルド。本番URLから改めてログイン/ホーム画面追加する。
- 理由: originが変わるため、プレビューの保存状態やホーム画面アイコンは自動で本番へ移らない。データ自体は同じクラウドに残る。
- 制約: pwa-checkは更新/削除しない。既存の更新ボタン・静的キャッシュを維持し、業務データの永続キャッシュを追加しない。
- 判断の状態: 採用中。

### D3: 無料枠を実際の指標と期間で確認する

- 採用する方法: 課金設定とHosting保存/日次・月次転送、Firestore日次read/write/delete・保存・月次送信、Auth方式/メール制限を読み取りAPIまたはConsoleで確認する。取得不可や遅延を0とせず明記する。
- 理由: Sparkであることだけでは使用量を実測したことにならない。Hostingの料金表360MB/日と説明10GB/月には期間表記の差があり、日/月を両方調べ適用枠とも照合する。
- 代案・制約: 長期の無料運用保証はしない。課金先・有料監視・バックエンドを追加しない。必要なConsole操作だけ段階的に案内する。
- 判断の状態: 採用中。

### D4: 既存検証基盤で公開前後を確かめる

- 採用する方法: TDDでフッター変更を確認し、check・全Emulator統合・PWAを通す。公開URLで起動→ログイン画面→空入力検証/再読み込みの表示と認証前のアクセス拒否・manifest/SW/キャッシュを検証する。
- 理由: 小さな表示変更でも既存PWAと共有機能を維持するため。Browser plugin not availableのため、既存Playwrightを使い390/1280pxの画像とエラーを確認する。
- 制約: 実クラウドで自動アカウント作成・メール送信・個人データ書き込みは行わない。本人操作と自動テストを区別する。
- 判断の状態: 採用中。
