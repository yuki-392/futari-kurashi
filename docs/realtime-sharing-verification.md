# iPhone＋PC・テスト用2アカウントでの共有確認

Phase 1・項目5。[実装記録0007](./implementation-log/0007-realtime-sharing.md)に設定・公開情報・結果を記録します。今回の共有対象は世帯名・所属・参加人数です。

## 接続先とデータの扱い

- 専用プロジェクト: futari-kurashi-5fcab9（Spark、請求先未接続）
- Firestore: (default)、Standard / Native、東京 asia-northeast1、無料枠対象、削除保護有効、PITR無効
- 検証チャネル: pwa-check。公開後の識別子はsharing-check
- [検証URL](https://futari-kurashi-5fcab9--pwa-check-uol8w76f.web.app)
- 有効期限: **2026-10-26 16:43（日本時間）**。Hostingバージョン: b4809b86c193c2d0。Rulesソースはテスト済みローカル版と一致を確認済み。

プレビューも実際のAuth・Firestore・Rulesへ接続します。今回は本人の希望により、AをiPhone、BをPCとし、別々のテスト用アカウントを使います。URLの公開期限が切れてもテスト用アカウント・世帯・Firestore・Rulesは残ります。既存の実用アカウントや世帯も削除しません。コード・パスワード・メール内リンクをチャット・実装記録に記載しません。実データの自動削除や確認済みフラグの手動変更は行いません。

## まず2台を準備する

1. AはiPhoneのホーム画面アプリを追加または更新し、BはPCブラウザーで検証URLを開きます。両方で最下部がsharing-checkになることを確認します。
2. 既存の実用アカウントでログイン中ならログアウトし、それぞれ別のテスト用アカウントでログインします。未登録なら本人が受信できるメールで登録し、確認メールからメール確認を済ませます。届かない場合は迷惑メールも確認します。登録・メール操作は本人が行います。
3. Aは今回操作するホーム画面アプリ内でログインを確認します。Bは再起動後の状態維持を確認するため、プライベートモードを使わず、同じブラウザープロファイルを使います。
4. Aの機種・iOS、BのOS・ブラウザー名とバージョンを記録します。パスワードやメールアドレスを伝える必要はありません。

## 世帯の作成と招待

1. **世帯を作成するのはAだけです。Bは世帯を作成せず、招待で参加します。** 脱退・削除・作り直しは今回未実装です。
2. Aで「共有確認用」などテスト用と分かる世帯名を入力して作成し、「参加人数：1 / 2人」を確認します。
3. AでBが実際にログインしているメールを指定し、招待コードを発行して本人同士で渡します。相手へのメッセージ送信は本人が行います。
4. 発行したコードを取り消し、Bでそのコードを確認すると共通の無効案内になることを確認します。
5. Aで再びコードを発行し、さらに再発行します。Bで再発行前のコードが無効になることを確認します。
6. 最新コードをBへ渡し、Bで招待を確認します。世帯名が正しいことを確認します。まだ「参加する」は押さず、次の手順に進みます。

## 再読み込みなしの共有

1. 両端末をオンラインにし、Aの「参加人数：1 / 2人」が見える画面を前面に表示します。
2. Bで「参加する」を押します。
3. **Aを再読み込みせず**「参加人数：2 / 2人」とパートナー参加済みへ変わることを確認します。おおよその反映時間も記録します。
4. 両端末で同じ世帯名と2人の参加状況になることを確認します。

10秒程度待っても変わらない場合は、画面の案内・通信状態・発生した操作を確認し、それ以上の参加操作を繰り返さず状況を伝えてください。権限を開放したり、データを削除したりして回避しません。

## 再起動・復帰・ログアウト

1. Aはホーム画面アプリを終了して再起動します。Bはブラウザーを終了して同じプロファイルで開き直し、検証URLへ戻ります。両方で同じ世帯と2人の状態が残ることを確認します。
2. 別アプリへ切り替えて戻り、所属が正しく表示されることを確認します。
3. 通信を切った後に戻し、復帰後も正しい所属へ戻ることを確認します。通信断中の共有や世帯データの永続オフライン利用は今回の対象外です。
4. Bでログアウトし、Bの世帯表示が消えること、Aでは2人の世帯のままであることを確認します。ログアウトは世帯の脱退ではありません。
5. Bで同じアカウントへ再ログインし、元の世帯へ戻ることを確認します。
