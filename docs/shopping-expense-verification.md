# 買い物と支出登録の連携の確認（Phase 2・項目5）

[実装記録0022](./implementation-log/0022-shopping-expenses.md)が判断と検証結果の基準です。2026-10-24に削除ボタンのR1修正も含め本人確認済みで、項目5は完了です。

## 動作

- 購入時に購入だけ/支出も登録を選び、キャンセルでは変更しません。購入だけの場合は購入済みから後で登録できます。
- 支出は商品名・日本時間の今日・有効な対応標準カテゴリから開始。実際の総額を入力し、予定予算/数量から金額を推測しません。支払者と割合は家計と同じ仕様で本人確認します。
- 1買い物項目から1回のみ。登録後は双方を独立して編集/削除し、支出削除後も同じ項目から再登録しません。再購入は新しい買い物か家計から記録します。
- 商品版・未登録・現在カテゴリをtransactionで確認し、購入/支出/不変リンク/精算月を原子的に保存します。通信断では書かず、競合でも入力を保持します。

## 本人確認手順

既存iPhone＋Mac／Chrome・テスト用2アカウントで行います。実生活の金額や認証情報は不要です。

1. 買い物で食品・予算500円の商品を追加。購入のキャンセルでは残り、購入だけでは支出が増えず、相手へ購入済みが反映されることを確認します。
2. 購入済みから支出に登録し、初期の商品名・今日・対応する有効なカテゴリ（使えなければ本人が選択）、金額が空欄であることを確認。101円・本人払い・50:50で保存し、相手の家計/合計・ホーム・予算残額・精算（支払者51円/相手50円）へ反映することを確認します。
3. 別の商品をホームから購入し、支出も登録で実額を保存します。購入状態と支出が両端末に反映されることを確認します。
4. 支出の編集で元の商品が自動変更されず、商品の編集でも登録した支出が自動変更されないこと、未購入へ戻して再購入しても同じ商品から支出を二重登録できないことを確認します。
5. 商品の削除で支出は残り、支出の削除で商品は残ること、支出を削除しても登録済み案内が残り再登録できないことを確認します。確認用データだけで試してください。
6. 両端末の再起動後も登録状態を維持し、片方のログアウトで非表示・再ログインで復帰することを確認します。

同時操作や権限改ざんは自動検証対象です。2026-10-24にR1の本人確認も完了しました。
